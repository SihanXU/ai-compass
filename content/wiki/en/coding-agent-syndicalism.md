summary: "Software is the first workplace agents take over; agents that read repos, write code and run tests are the vanguard of useful AI."

## Beliefs

Coding-Agent Syndicalism believes the decisive unit of AI progress is not the chat answer but the merged change. Give a model a repository, a shell, a test suite and a loop, and it can read, edit, run, fail, read the error and try again, much as a working engineer does. Code is the ideal proving ground because it comes with its own judge: compilers and tests say yes or no without a human grader. The "syndicalism" is the conviction that agents should organize around the actual work, with the tools of the trade in their own hands.

It sits just left of center, since code is a formal language but one that touches real systems, and in the upper Harness half, because the power comes from the loop of tools, execution and feedback rather than from a single forward pass. Its paradigm level is mildly progressive: it extends existing models more than it overturns them.

## Arguments

- Benchmarks built from real repository issues give a concrete, execution-checked measure of progress, and agent scaffolds have pushed it steadily upward.
- Executable feedback is a dense, cheap and honest reward signal, useful for both inference-time retries and training.
- Agents that improve developer tools improve their own tools, a practical feedback loop that few other domains offer.

## Critiques

- Passing tests is not the same as correct, maintainable code; agents can overfit to visible tests or quietly weaken them.
- Success in software may not transfer to domains that lack a cheap, automatic verifier, so the vanguard may be leading into a cul-de-sac.
- Benchmark contamination and narrow task selection can make headline numbers look better than everyday reliability.
