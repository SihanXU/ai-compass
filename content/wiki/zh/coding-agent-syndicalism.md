## 主张

编程智能体工团主义认为，衡量 AI 进步的关键单位不是一条聊天回答，而是一次被合并的改动。给模型一个代码仓库、一个 shell、一套测试和一个循环，它就能读、改、跑、失败、看报错、再试，像一个真正干活的工程师一样。代码是理想的练兵场，因为它自带裁判：编译器和测试直接给出对或错，不需要人来打分。所谓"工团"，就是相信 agent 应该围绕真实的工作组织起来，把生产工具握在自己手里。

它在图上略偏语言一侧——代码是形式语言，但它会触碰真实系统；又处在 harness 半区上部，因为能力来自工具、执行和反馈组成的循环，而不是一次前向传播。范式等级略偏革新：它更多是在延伸现有模型，而不是推翻它们。

## 论据

- 基于真实仓库 issue 构建的 benchmark 提供了具体、可执行验证的进步度量，各种 agent scaffold 一直在把分数往上推。
- 可执行反馈是密集、便宜又诚实的奖励信号，既能用于推理时重试，也能用于训练。
- 改进开发工具的 agent 也在改进自己的工具，这种现实的反馈闭环是很多别的领域没有的。

## 批评

- 测试通过不等于代码正确、可维护；agent 可能过拟合可见测试，甚至悄悄把测试改弱。
- 软件领域的成功未必能迁移到没有廉价自动 verifier 的领域，先锋队可能领着大家走进死胡同。
- benchmark 污染和狭窄的任务选择，会让头条数字比日常可靠性好看得多。
