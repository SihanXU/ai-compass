## 主张

函数调用联邦主义在工具使用的基础上加了一部宪法：schema。每种能力——数据库、支付服务、图像生成器，或者另一个模型——都是有自己类型化接口的主权州；语言模型是联邦政府，负责路由请求、组合结果，但从不伸手进州里。结构化的 JSON 参数、经过校验的输出和清晰的契约让联邦井然有序，新州只要发布一个 schema 就能加入。

它位于 Language 一侧（第 4 列），在中线左边一点，偏向 Harness（第 7 行）：模型用结构化文本说话，干活的是一个服务联邦。中性颜色说明 function calling 如今已是标准基础设施。工具使用自由派赞美的是模型使用工具的自由，联邦派关心的则是让这种自由安全、可组合的规则：类型化参数、权限和可预测的失败。

## 论据

- 类型化 schema 让工具调用可以被机器检查，减少格式错误的请求，让失败显式化。
- 把能力包装成 API，系统就能集成在各自细分领域胜过任何通才的专用模型和服务。
- 在大规模 API 集合上微调的模型，能学会选择和调用并没有人手专门接线的 API。

## 批评

- computer use 派认为，大多数软件根本没有干净的 API，只有 GUI 级别的智能体才够得着。
- 庞大的工具目录会挤占上下文、降低选择准确率，而且服务一变 schema 就会漂移。
- 单体派把这个联邦看成胶水代码，认为足够强的单一模型迟早会把它吞掉。
