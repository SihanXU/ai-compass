## 主张

Harness 自由主义认为，同一个模型可以是平庸的聊天机器人，也可以是能干的 agent，区别全在外面包了什么。harness 就是权重之外的一切：反复调用模型的循环、它能调的工具、它能碰的文件系统和 shell、它读取的记忆、帮它抓错的 verifier 和测试，以及让这一切对模型"可读"的接口设计。好的 harness 设计是工程，而工程是会复利的。

它在图上略偏语言一侧（harness 用文本和模型对话），位于 harness 半区的上部，离中线不远，说明它仍然尊重模型这台引擎。它是"自由主义"而非激进派：不像更靠下的 harness 虚无主义那样宣称模型无所谓，只是说再好的引擎没有底盘也跑不起来。范式等级略偏革新。

## 论据

- ReAct 式的循环把推理和行动、观察交错起来，在需要新信息的任务上胜过纯推理。
- 关于 agent-computer interface 的工作表明，模型不变，只重新设计工具命令和反馈格式，软件工程任务的成功率就会大幅变化。
- verifier、测试和重试，能把一个单次成功率一般的模型变成端到端可靠得多的系统。

## 批评

- 单体派指出，harness 里的技巧经常被下一代模型直接吸收，harness 投入折旧很快。
- 复杂的 harness 会变成脆弱的定制软件，贴合某个模型的脾气，一升级就坏。
- 功劳很难分清：惊艳的 agent demo 到底靠 harness 还是靠模型，往往说不清，容易夸大。
