## 主张

提示词手工业主义把 prompt 当成匠人的作品。合适的角色、按合适顺序排列的示例、对约束和输出格式的恰当措辞——每一个选择都可能让结果大幅波动，而匠人凭多年经验知道该怎么选。别人把 prompting 看成临时 hack，手工业派却视之为真正的技能，更接近编辑或教学而非编程，手边总有一本翻旧了的“好用模板”笔记。

它位于靠近 Language 最左端的位置，因为一切都发生在自然语言里；纵轴略低于中线、偏向 Harness，因为 prompt 是包在固定模型外面的脚手架，而不是对模型本身的修改。正统的色号代表对主流大模型配方的忠诚：prompt 手艺是大模型早期的标志性实践，新派别更爱谈上下文工程、自动 prompt 优化，或者干脆是不需要哄的模型。手工业派并不在意——手工货照样有人买。

## 论据

- few-shot 示例、指令和格式选择不动权重就能显著改变任务准确率。
- prompting 便宜、立竿见影、非专业人士也能上手，常常是从模型到可用产品最快的路径。
- 写得好的 prompt 本身就是人类可读的行为文档，不像微调后的权重那样不透明。

## 批评

- 结果很脆弱：措辞稍改或者模型换个版本，精调过的 prompt 就可能失效。
- 自动 prompt 优化和更好的指令微调模型正在稀释手工技艺的价值。
- 批评者认为 prompt 经验之谈多半是轶事，很少经过有对照的认真评测。
