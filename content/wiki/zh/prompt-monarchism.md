## 主张

提示词君主制认为，system prompt 就是王冠。一段写得好的指令，放在上下文最顶端，定义模型的人设、规则、语气、拒答策略和任务流程，而模型处处遵从。工作流、router、微调和外部护栏，在它看来都是多余的衙门：行为不对，就重写诏书。

它位于图表左上部。语言分数极高，因为治理完全通过自然语言文本进行。单体倾向来自它只依赖“一个模型加一段 prompt”，周围没有任何系统。它的范式分数是不折不扣的老派：这是早期聊天时代在语言模型上做应用的默认方式，而后来的上下文工程和 agent 设计，在一定程度上正是以反对它来定义自己的。

## 论据

- 经过指令微调的模型对详细 system prompt 的遵循已经足够好，很多应用除此之外几乎什么都不需要。
- 单个 prompt 迭代成本低，容易做版本管理，非工程师也看得懂。
- 上下文中的指令能让模型立刻适应新任务，无需训练，也无需基础设施。

## 批评

- 冗长的单体 prompt 会变得脆弱：指令彼此冲突，埋在上下文深处的会被忽略，还容易遭到 prompt injection。
- 一段静态 prompt 无法提供复杂任务所需的特定数据、工具和记忆。
- 上下文工程派认为，prompt 只是模型所见内容中很小的一部分，而且很少是最重要的那部分。
